Executive Summary

The AI Semester Orchestrator is an enterprise-grade cloud-native application designed to eliminate curriculum fragmentation in higher education. Higher education students consistently receive disjointed academic calendars, course syllabi, and lecture slide decks in unstructured PDF formats. This project implements a decoupled three-tier cloud architecture spanning Microsoft Azure (App Service / Container Apps, Azure Container Registry, Azure OIDC) and Vercel Global Edge CDN, tightly integrated with a managed PostgreSQL database utilizing the pgvector extension and cloud LLM APIs.

The core engine utilizes an autonomous multi-agent LangGraph workflow that ingests unstructured course documents, performs collision-free calendar scheduling, indexes high-dimensional document embeddings, and generates an interactive 15-week study roadmap with dynamic concept summaries and self-scoring knowledge checks. Fully automated continuous integration and continuous deployment (CI/CD) is achieved through GitHub Actions utilizing secretless OpenID Connect (OIDC) federated credentials.

1. Problem Statement & Motivation

In modern university curricula, students are confronted with four acute operational hurdles:

  1. Curriculum Fragmentation: Syllabi list course topics and learning objectives, while university academic calendars separately mandate semester boundaries, breaks, and exam weeks.
  2. Pacing & Collision Failures: Students frequently fail to anticipate midterm collision weeks or balance lecture pacing against major deadlines.
  3. Manual Study Guide Synthesis: Manually reviewing hundreds of pages of lecture slides and transcripts to construct study guides and self-assessment quizzes requires dozens of hours weekly.
  4. Local Compute Constraints: Running semantic document chunking, 1536-dimensional vector search, and agentic LLM orchestration locally on client laptops drains battery, suffers from long cold-start latencies, and lacks cross-device persistence.

Cloud Computing Rationale: A public cloud deployment is essential to decouple stateless client interactions from heavy containerized backend workloads, enable elastic horizontal scaling during exam review surges, ensure continuous availability via health checks, and manage high-dimensional vector search at scale.

2. Objectives

  • Public Cloud Deployment: Architect and deploy a robust multi-tier system on Microsoft Azure and Vercel.
  • Microservice Containerization: Encapsulate the asynchronous Python FastAPI application in Docker containers published to Azure Container Registry (ACR).
  • Automated DevOps CI/CD: Establish a continuous integration and deployment pipeline in GitHub Actions with secretless OpenID Connect (OIDC) authentication.
  • Multi-Agent LangGraph Orchestration: Coordinate Extraction, Scheduling, Retrieval, Generation, and Quality Control agents to parse documents and synthesize curricula.
  • High-Dimensional Vector Search: Deploy managed PostgreSQL with pgvector for cosine similarity indexing over 1536-dimensional embeddings.
  • Fault-Tolerant Edge Presentation: Deploy a Next.js frontend to Vercel's global CDN with client-side synthesis fallback ensuring zero error screens.

3. System Architecture

The application implements a decoupled, three-tier cloud-native architecture ensuring fault isolation and horizontal scalability:

Figure 1: End-to-End Three-Tier Cloud System Architecture across Vercel, Microsoft Azure, and Cloud AI Services.

Architectural Tiers:

  • Presentation Tier (Vercel Edge): React 19 / Next.js 16 App Router application distributed across global edge CDN nodes, providing sub-50ms latency, automatic SSL termination, and client-side fallback resilience.
  • Application Tier (Microsoft Azure): Containerized FastAPI backend running on Azure App Service for Containers (aisemester-app-21335) backed by Azure Container Registry (ACR), featuring continuous health monitoring via /health.
  • Data & AI Tier: Cloud PostgreSQL instance enabled with pgvector for storing 1536-dimensional semantic chunk embeddings, coupled with OpenAI GPT-4o for generative synthesis.

5. Multi-Agent Pipeline Implementation

The core planning intelligence is coordinated through a LangGraph state graph consisting of five specialized autonomous agents:

Figure 2: LangGraph Autonomous Multi-Agent State Machine and Quality Control Feedback Loop.
  1. Extraction Agent: Ingests syllabus and academic calendar PDFs using pypdf and extracts topics, semester start/end dates, and university breaks into validated Pydantic schemas.
  2. Scheduler Agent: Executes calendar arithmetic to distribute topics across 15 teaching weeks, slots designated Midterm Assessment Weeks (Week 7), and shifts curriculum around university holidays (Week 11).
  3. Retrieval Agent: Converts weekly curriculum queries into 1536-dimensional vector embeddings via text-embedding-3-small and runs cosine similarity searches against PostgreSQL (k=10 chunks).
  4. Generator Agent: Synthesizes detailed concept mastery summaries and four-option multiple choice questions with grounded explanations using GPT-4o.
  5. Quality Control (QC) Agent: Inspects generated questions for factual grounding against lecture context chunks. If groundedness scores fall below threshold, it triggers an automated retry cycle (up to 3 attempts).

6. Cloud DevOps, Security & CI/CD Pipeline

To meet cloud enterprise standards, the deployment pipeline completely eliminates static administrative passwords in favor of OpenID Connect (OIDC) federated credentials:

name: Deploy Backend to Azure Web App
on:
  push:
    branches: [main]
    paths: ['backend/**']

jobs:
  build-and-deploy:
    runs-on: ubuntu-latest
    permissions:
      id-token: write
      contents: read
    steps:
      - uses: actions/checkout@v3
      - name: Log in to Azure via OIDC
        uses: azure/login@v2
        with:
          client-id: ${{ secrets.AZURE_CLIENT_ID }}
          tenant-id: ${{ secrets.AZURE_TENANT_ID }}
          subscription-id: ${{ secrets.AZURE_SUBSCRIPTION_ID }}
      - name: Build & Push to ACR
        run: |
          az acr login --name ${{ env.ACR_NAME }}
          docker build -t ${{ env.ACR_NAME }}.azurecr.io/${{ env.IMAGE_NAME }}:${{ github.sha }} ./backend
          docker push ${{ env.ACR_NAME }}.azurecr.io/${{ env.IMAGE_NAME }}:${{ github.sha }}
      - name: Deploy to Azure Web App
        uses: azure/webapps-deploy@v2
        with:
          app-name: ${{ env.WEBAPP_NAME }}
          images: ${{ env.ACR_NAME }}.azurecr.io/${{ env.IMAGE_NAME }}:${{ github.sha }}
